Why DuckDB 2.0 is faster

DuckDB 2.0 的 Alpha 版本現已推出，正式版預計今年秋季發布，重點提升了查詢速度與功能。其中最顯著的改進是針對 Amazon S3 查詢的非同步 I/O，可將速度提升兩到三倍，因其採用獨立的下載執行緒池預先讀取資料，而使用者無需更改任何查詢語句。此外，遞迴 CTE 引擎也已重寫，處理深層次父子關係資料集的效能提升高達數十倍。這些新功能對資料管線開發者來說，能大幅優化資料處理效率。 - 主要速度提升來自 S3 非同步 I/O，透過背景預讀實現更快的雲端資料存取。 - 遞迴 CTE 引擎重寫，極大加速了圖形遍歷和層次結構查詢。 - 新增觸發器、CTE 中的 DML 等多項 SQL 功能，增強了資料庫的靈活性和自動化能力。

DuckDB 2.0 中針對 S3 查詢的非同步 I/O 功能，具體是如何實現 2 到 3 倍的速度提升？

DuckDB 1.5.5 中，每個工作執行緒輪流執行網路下載和資料解碼。而在 2.0 版本中，DuckDB 引入了一個獨立的執行緒池專門負責資料下載，並將資料緩衝起來。這使得工作執行緒可以持續地從緩衝區中獲取資料進行解碼，實現網路和 CPU 的同時高效利用，從而顯著加速查詢。

遞迴 CTEs 的改進對於哪些資料處理任務或場景會帶來最大的效益？

遞迴 CTEs 的強化對於處理具有深層次父子關係的資料集，如組織架構圖、社交網絡圖或物料清單（BOM）等，效益最為顯著。例如，在分析圖形的可達性、查找層次結構中的所有祖先或後代，或是追蹤複雜數據流時，其大幅提升的性能將大大縮短查詢時間。

除了主要的性能提升之外，DuckDB 2.0 還引入了哪些其他新功能來增強其對資料工程師和分析師的實用性？

DuckDB 2.0 引入了多項新的 SQL 功能，包括資料庫端的觸發器（Triggers），允許在 CTE 中執行資料操作語言（DML），以及巢狀結構的 Schema 定義。此外，它還支援 Spark SQL 相容模式，並能將遠端檔案緩存溢出到磁碟，這些都極大地提升了資料處理的靈活性、自動化能力及效率。

月海是什麼？為什麼月球背面幾乎沒有月海？

月海是月球正面大面積、平坦、顏色較深的區域，是由古代火山噴發的玄武岩熔岩流填滿大型撞擊盆地後凝固形成的。月球背面缺乏月海，很可能是因為其地殼比正面厚，使得月球內部的熔融物質難以穿透地殼到達表面。

如果月球背面總是背對地球，月球偵察軌道器是如何拍攝到它的影像的？

月球偵察軌道器 (LRO) 是一艘環繞月球運行的太空船。它在繞月軌道上運行時，可以自由地拍攝月球表面的任何區域，包括背面，而不受地球觀測角度的限制。這些影像隨後被傳回地球，供科學家研究。
