Push ifs up and fors down: The idiom, its algebra, and its limits

「將 If 語句上推，將 For 迴圈下放」是一種程式設計原則，旨在提升程式碼的清晰度與執行效能。此原則建議將條件判斷 (if 語句) 移至呼叫者或處理流程的早期階段，以集中控制流並明確前置條件。同時，將迭代迴圈 (for 迴圈) 推遲到批次處理或資料過濾之後執行，以減少不必要的計算並有助於向量化，此模式也見於資料庫查詢優化。 * 將條件判斷上推，提早篩選輸入。 * 將迴圈下放，進行批次處理以提升效率。

「將 If 語句上推」具體是如何達到集中控制流和明確前置條件的呢？

透過讓呼叫者處理條件分支，例如在傳入 `Option` 前先處理 `None` 的情況，可以使被呼叫的函數只接收明確、已驗證的輸入。這樣一來，決策點集中在較高的層次，並且函數的型別簽章便能清楚地表達其所需的前置條件，降低內部複雜性。

為什麼「將 For 迴圈下放」有助於向量化 (vectorization)？

向量化是一種利用處理器單指令多資料 (SIMD) 能力的優化技術，能同時處理多個資料元素。將迴圈下放至批次處理函數內部，可以創造出一個沒有分支條件的「熱迴圈」(hot loop)，這種連續、預測性高的資料處理模式，非常適合現代處理器的向量化指令集，從而顯著提升執行速度。

文章提到此原則在資料庫查詢優化中，術語會「顛倒」，這是什麼意思？資料庫中「將 If 語句上推」的等效操作是什麼？

在資料庫查詢計畫中，資料流是從底層（表掃描）向上流向根部（結果），因此「向下推動」謂詞（predicates）意味著在執行流程中盡早評估它們。這就等同於程式設計中「將 If 語句上推」，即盡早進行選擇（`WHERE` 子句）和投影（`SELECT` 特定欄位），以減少後續操作處理的資料量，達到早期過濾的效果。
