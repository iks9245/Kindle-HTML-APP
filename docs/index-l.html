Introducing System One Models and Jev

TypeSafe AI 創辦人 Diogo Almeida 於 2026 年 9 月 15 日宣布，該公司正式發布其首個「System One Model」模型 Jev。這款新型邊緣模型旨在為軟體提供快速、結構化的決策，以推動大規模自動化。Jev 在處理「System One 任務」時展現與現有大型語言模型相當的智能水平，但速度和效率卻高出兩個數量級，且專為結構化輸出優化，完全不會產生幻覺。 * 專為軟體自動化設計，而非通用聊天。 * 透過專注於結構化、無幻覺的輸出，實現極高的速度和效率。

文章中提到的「System One Model」和「System One 任務」具體指的是什麼？

「System One Models」的命名靈感來自丹尼爾·卡尼曼的《思考，快與慢》，指的是像人類快速、直覺式思考般運作的模型。這些模型專注於需要快速、結構化且具有校準機率的決策任務，通常涉及處理程式的特定狀態而非自由形式的文本生成。

Jev 模型如何實現比現有大型語言模型顯著更快的速度和效率，同時有哪些限制？

Jev 透過全新的模型架構、專為效率設計的平行採樣器，以及名為「強化學習校準決策 (RLCD)」的訓練方法實現其高速和高效率。它主要輸出預先定義的、類型安全的結構化數值，而非像傳統大型語言模型那樣生成自由形式的字符串，這使其無法產生幻覺，但同時也限制了其通用文本生成能力。

考量到 Jev 的特性，它主要適合哪些實際應用場景？

鑑於 Jev 擅長快速、結構化且具校準機率的決策，其主要應用場景是軟體自動化中需要直接可用的智能「函數呼叫」。這可能包括根據非結構化輸入進行分類、自動化流程中的決策點、參數設定或任何需要快速且可靠地產生類型安全結構化輸出的任務。

為什麼作者團隊能在短短一個月內完成通常需要數年的 GPU 驅動程式開發？

團隊利用先前開發的虛擬機進行 macOS 逆向工程，並透過對硬體進行探測和追蹤來理解 AGX 韌體 ABI 及使用者空間元件，而不是直接查看 Apple 的二進制檔案。這種高效的「潔淨室」方法結合專業知識，大大縮短了開發時間。

成功開發此 Linux GPU 驅動程式對 M4 Mac Mini 和 MacBook Neo 的未來有何意義？

這項成功意味著 M4 Mac Mini 和 MacBook Neo 在運行 Linux 時將能獲得完整且高效能的圖形加速支援。這不僅能大幅提升這些裝置在 Linux 環境下的可用性和使用者體驗，也為開源社區在 Apple Silicon 上實現更全面的 Linux 支援奠定了基礎，未來可能還會進一步支援 Vulkan。

驅動程式開發過程中最大的技術挑戰是什麼？

驅動程式開發中最具挑戰性的部分是逆向工程 AGX 的韌體 ABI (應用程式二進位介面)。Apple 的設計將核心驅動程式切半，一部分放入 AGX 韌體，另一部分則透過共享記憶體中交錯複雜的結構體進行通訊，導致理解和實作其互動模式極為困難。
