目前的查詢最佳化器為何在處理連接順序等任務時常不盡理想？

查詢最佳化器，特別是在處理多表連接（join ordering）時，面臨著巨大的計算複雜性，因為連接順序的排列組合數量會隨著表數量的增加而呈指數級增長，這是一個已知的NP-hard問題。因此，傳統的最佳化器往往只能採用啟發式演算法，無法保證找到全局最優解，導致其生成的查詢計畫可能不夠高效。

語言模型通常用於處理文本，它是如何學會最佳化資料庫查詢計畫的？

語言模型學習最佳化查詢計畫的關鍵在於其具備學習具有易於驗證輸出的任務的能力。由於查詢計畫的優劣可以透過實際執行時間直接衡量，作者透過監督式微調（SFT）教授模型產生基本計畫，再利用強化學習（RL）根據計畫的執行速度給予獎勵，不斷強化模型生成更快計畫的行為。

這項研究對於資料庫管理系統或其他複雜最佳化問題有何潛在的更廣泛影響？

這項研究顯示，透過AI（特別是強化學習）來解決資料庫最佳化等複雜NP-hard問題具有巨大潛力，未來可能導致更智能、自適應的資料庫管理系統。這種方法也可推廣到其他需要從海量可能解中找出最佳方案的工程或科學領域，例如供應鏈最佳化、資源調度或演算法設計。

Breaking the 1.58-bit Barrier for Ternary LLMs

研究人員於 2026 年 9 月 14 日在 arXiv 上發表了論文《突破三元大型語言模型 1.58 位元障礙》，提出了一種名為 BITCOS 的新型數據儲存佈局。該方法利用三元 LLM 中零權重分佈不均的特性，成功將每權重儲存位元數降至 1.485 位元，打破了傳統上 1.58 位元的限制。這項創新顯著提升了三元 LLM 的儲存效率，並在不同平台上實現高達 1.28 倍的矩陣乘法加速和 1.27 倍的推斷吞吐量提升，使其在實際部署中更具可行性。 * BITCOS 利用稀疏性，超越了傳統的五三元組打包方式，節省了儲存空間。 * 該技術在 CPU 和 GPU 上均能有效加速大型語言模型的解碼過程。

為什麼傳統上認為三元 LLM 的每個權重需要 1.58 位元？

傳統上，三元大型語言模型 (LLM) 的權重符號為 $\{-1, 0, +1\}$。由於有三種可能的符號，根據資訊理論，每個符號至少需要 $\log_2 3 \approx 1.585$ 位元來表示，因此這個數字成為了理論上的儲存下限。

BITCOS 是如何突破傳統 1.58 位元限制的？其核心創新點是什麼？

BITCOS 的核心創新點在於它認識到三元 LLM 中零權重的分佈不均，即零的出現頻率遠高於假設的均等分佈。它採用了一種分佈自適應佈局，由一個密集的「存在位元圖」和一個壓縮的「符號向量」組成，專門利用零的密度來更有效地儲存權重。

這項研究對未來三元 LLM 的實際部署和應用有何重要意義？

這項研究透過顯著降低儲存成本和提高推斷速度，使三元 LLM 在資源受限的設備（如邊緣設備或移動裝置）上部署變得更加可行。更高效的模型運作也意味著更低的能耗和更快的響應時間，這對於推動 LLM 的廣泛應用至關重要。
