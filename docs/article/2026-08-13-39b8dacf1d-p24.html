延伸問答

「HTML over WebSockets」這種技術解決了傳統 SPA 開發模式的哪些痛點？

傳統 SPA 通常需要獨立的前端 JavaScript 框架和後端 API，導致兩套獨立程式碼庫透過複雜的合約相互理解，增加了開發的複雜度和溝通成本。HTML over WebSockets 透過將所有渲染邏輯移至後端，並直接傳送 HTML，簡化了架構、減少了對 API 合約的需求，並允許以單一語言棧進行開發，從而提升效率。

對於前端和後端開發者來說，採用「HTML over WebSockets」這種模式會帶來什麼樣的影響？

對後端開發者而言，他們將承擔更多渲染邏輯和介面控制的責任，但可以在自己熟悉的語言和環境中完成更多工作。前端開發者則無需處理複雜的視圖渲染，主要職責是建立 WebSocket 通道、放置接收到的 HTML，以及處理次要的動畫和事件。這種模式促進了團隊在單一技術棧上的協作，潛在地加速了開發週期。

雖然文章提到這種技術的優點，但它在什麼情況下可能不適用，或者有哪些潛在的局限性？

HTML over WebSockets 最適合需要雙向、低延遲即時通訊的應用，如聊天室或協作工具，但並非所有情況都適用。如果應用僅需從伺服器單向推播更新，SSE (Server-Sent Events) 可能更簡單且經濟；如果一般的請求-回應模式已足夠，HTTP 上的超媒體（如 htmx）會是更好的選擇。此外，所有的渲染邏輯都在伺服器端，可能會增加伺服器的負載和狀態管理的複雜性。
