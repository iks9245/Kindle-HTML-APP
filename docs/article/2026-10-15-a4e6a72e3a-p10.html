延伸問答

OpenCode 2.0 的核心服務作為單一背景行程自動運行，這對使用者或開發者有何實際益處？

這種設計讓所有 OpenCode 介面（如 TUI、網頁介面、桌面應用程式）都能與同一個中央行程溝通，確保資料與狀態的一致性。它還能讓透過程式化客戶端（@opencode/client）編寫的腳本自動發現並使用本地服務，特別適合用於排程任務，從而簡化了開發和管理流程。

OpenCode 2.0 的「程式碼模式」具體是如何運作的，它能讓代理程式實現哪些以往難以達成的高效操作？

程式碼模式內建了一個精簡的 JavaScript 解譯器，能將 MCP 伺服器或 OpenAPI 端點轉換為代理程式可呼叫的函數。這使得代理程式可以在單一往返中，編寫腳本來呼叫工具、處理結果再呼叫另一個工具，大幅減少了傳統上需要多次單獨呼叫的複雜性，提升了任務執行效率。

OpenCode 2.0 的強化插件系統和背景任務處理能力，如何進一步擴展代理程式的功能和開發彈性？

插件系統現在有超過 80 個內部插件，保證了 API 的維護性，並支援熱重載，讓代理程式可以在會話中即時編寫並使用新插件。背景任務能力則允許主代理程式啟動子代理或異步執行殼層命令，實現多工處理，即便長時間運行任務也不會阻礙主代理的工作，極大提升了代理程式的平行處理和自定義能力。
