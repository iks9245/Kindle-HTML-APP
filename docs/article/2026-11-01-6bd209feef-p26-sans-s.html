延伸問答

什麼是「use-after-free」漏洞，為何它的嚴重性如此之高？

「use-after-free」漏洞是指程式在釋放記憶體後，又再次嘗試使用該記憶體，可能導致記憶體損壞、程式崩潰，甚至允許攻擊者執行惡意程式碼。此漏洞特別危險，因為它在 TCP 握手階段發生，攻擊者無需任何憑證即可遠端觸發，進而取得系統的完全控制權。

文章中提到「多路徑 TCP 監聽器」與 Go 程式，這如何使此漏洞更具危險性？

多路徑 TCP 監聽器允許 TCP 連線同時利用多個路徑，而 Go 程式預設會開啟這類監聽器。Anthropic 的研究指出，其概念驗證漏洞利用程式能針對啟用多路徑 TCP 監聽的伺服器取得 root 權限，這表示許多預設配置的 Go 應用程式伺服器面臨更高的風險。

對於尚未發布修補程式的 Linux 發行版用戶，應如何應對此漏洞？

由於許多主流發行版尚未提供修補程式，用戶應密切關注其發行版的安全公告，並盡快更新核心。同時，考慮實施臨時緩解措施，例如限制對受影響 TCP 埠的網路訪問，或禁用多路徑 TCP 功能，以降低潛在的攻擊風險，直到官方修補程式可用為止。
