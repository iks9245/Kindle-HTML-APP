延伸問答

這次 8 月 17 日的服務中斷與之前發生過的事件有何不同？其根本原因為何？

這次中斷的主要原因是流量達到新高峰時，美國中部資料中心的關鍵基礎設施組件未能按需求擴展容量，而非程式碼或配置錯誤。與 8 月初的另一次 Actions 故障一樣，這兩起事件的核心都是容量不足。

GitHub 如何具體解決這些底層的容量問題，並確保未來系統的穩定性？

GitHub 正透過多管齊下的方式解決容量問題，包括增加數百萬個 CPU 核心和大量儲存空間，並加速將平台遷移至 Azure。他們還致力於改進操作實踐，如加強測試、更安全的部署、更好的可觀察性和警報系統，同時隔離關鍵系統以減少潛在故障的影響。

考慮到開發者對 GitHub 的高度依賴，公司對未來的平台可靠性有何具體承諾？

GitHub 承諾會透過提升平台的擴展性和可靠性來重新贏得開發者的信任。他們將從每次故障中學習，並將相關工作納入可用性工作流程，例如應用一致的重試限制和審查低優先級警報，以防止未來的級聯故障。
