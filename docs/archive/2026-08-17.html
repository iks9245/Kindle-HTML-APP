Models Are Getting Dumber on Purpose

近期，AI模型正刻意犧牲龐大的事實知識儲存，轉而專注於強化其推理能力，導致模型在特定基準測試上表現出「更聰明」的表現，儘管整體知識儲備減少。這種趨勢使得模型參數數量大幅下降，例如GLM-5.2和Qwen3.5等，使其更小、更高效，足以在消費級GPU上運行。此策略旨在將容易過時且佔用空間的事實知識外包給外部工具或檢索系統，而模型本身則作為一個強大的「推理引擎」，以此解決幻覺問題並延長模型的核心價值。 * 模型目的性地捨棄大量事實知識，轉而提升推理能力。 * 這使得模型體積更小，能在消費級硬體上高效運行。 * 最終目標是結合外部知識庫，大幅減少幻覺並保持知識更新。

為什麼AI實驗室選擇犧牲模型的「事實知識」來增強「推理能力」？

這是因為事實知識佔用大量參數，更新迅速且容易過時，導致模型訓練成本高昂且易產生幻覺。相反，推理程序更為穩定且可壓縮，透過犧牲事實儲存能讓模型更小巧、更高效，並解決了過去事實錯誤難以修正的問題。

這種將事實知識外包給外部系統，而模型專注於推理的策略，如何解決目前AI模型常見的「幻覺」問題？

當事實知識儲存在模型權重中時，錯誤的事實難以追蹤和修正。但若事實來自外部可更新的知識庫，錯誤就有「地址」可查證。這樣一來，用戶可以編輯外部文件來修正錯誤，大幅減少了模型生成不實資訊的機率，並使修正過程更加透明和高效。

這些「刻意變笨」但推理能力強的模型，在哪些任務上會表現出色？而若沒有外部工具輔助，它們又會在哪方面遇到困難？

它們在數學、程式編碼等需要邏輯推理和步驟分解的任務上表現出色，因為這些程序相對穩定。然而，若沒有外部工具輔助，當被問及最新的時事、複雜的統計數據或特定領域的深層細節等純粹的事實問題時，這些模型將難以提供正確答案，甚至會傾向於編造資訊。

如果網站擁有者不希望 Cloudflare 注入分析腳本，他們應該如何操作？

網站擁有者應確保其域名在 Cloudflare DNS 設定中設為「僅限 DNS」（灰色雲朵圖標），而非「代理」（橙色雲朵圖標）。此外，如果已啟用代理，則需要在 Cloudflare 分析儀表板中手動啟用網站分析後再將其停用。

Cloudflare 為何會採取這種預設注入分析腳本的做法？

文章中提到，Cloudflare 可能認為其 CDN 代理服務是大多數用戶使用的預期預設功能，因此傾向於預設啟用相關服務。然而，許多用戶認為這應該是選擇啟用而非選擇停用的功能。

Cloudflare 靜默注入分析腳本對用戶網站的隱私和安全性有何潛在影響？

這種做法引發了對用戶數據隱私的擔憂，因為它在未經明確同意的情況下收集了網站訪客的分析數據。更廣泛地看，如果 Cloudflare 能夠在網站內容中注入腳本，理論上它也能夠監視加密流量，這對於網站的數據完整性和安全性構成潛在風險。
