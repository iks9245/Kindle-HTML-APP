為什麼開發者認為 Claude 的原始輸出需要被「去浮誇化」？

Claude 被描述為一位出色的工程師，但它有一個「無可救藥的狀況」：說話像是在為自己的 pull request 發表 TED 演講。它的回應常常過於戲劇化、冗長且充滿了「點擊誘餌」式的語言，使得直接獲取核心資訊變得困難。

Claudette 是如何實現將 Claude 的輸出轉換為「正常英文」的？

Claudette 的運作原理是將 Claude 的上次回應寫入一個臨時文件，然後透過 Gemini CLI 將該文件內容管道傳送給 Gemini 模型進行翻譯。Gemini 會根據指示將文本翻譯成簡潔明瞭的風格，其輸出會被 Claudette 如實打印，避免 Claude 再次介入修改。

Claudette 提供了哪些不同的「模式」，以及這些模式如何滿足不同用戶的需求？

Claudette 提供了三種主要模式：「colleague」（同事）模式輸出技術細節，適用於工程師；「manager」（經理）模式提供簡化、去除了程式碼的摘要，適用於技術相關的經理；而「director」（主管）模式則提供精簡的結果、影響和要求，適用於只需要快速了解要點的高管。這些模式讓用戶能根據不同受眾調整輸出內容，提高溝通效率。
