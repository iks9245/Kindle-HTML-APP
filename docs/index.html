Exploiting System Management Mode with a very long interrupt

研究人員發現了x86 CPU上系統管理模式 (SMM) 的一個新漏洞，允許攻擊者在特定條件下破壞其安全機制。此漏洞利用一個核心在執行「超長指令」時，未能及時響應SMM的同步進入請求，導致SMM要求所有核心同時進入或退出SMM的同步狀態被打破。這使得攻擊者可能在SMM運作期間，利用原本休眠的漏洞進行攻擊。目前，建議的權宜之計是避免執行任何超長指令，但長期修復方案仍不明確。 - 漏洞核心在於SMM的多核心同步機制失效。 - 透過執行耗時極長的機器指令來觸發。

什麼是系統管理模式 (SMM)，以及打破它為何如此嚴重？

SMM是x86 CPU上一個高度特權的執行環境，用於處理諸如電源管理或硬體控制等底層系統任務。破壞SMM意味著攻擊者可能獲得對系統的最高控制權限，繞過大部分安全防護。

這種「超長指令」是如何導致SMM同步失效的？

SMM要求所有核心同時進入或退出。當一個核心執行耗時極長的指令時，它無法及時響應另一個核心發出的SMM進入請求。發出請求的核心最終會因逾時而單獨進入SMM，從而破壞了SMM預期的同步狀態。

修復這個SMM漏洞面臨哪些主要挑戰？

修復此漏洞存在兩難：如果保留或增加等待超長指令完成的逾時時間，可能會導致性能下降或同步被破壞；如果移除逾時，則一個合法停滯的核心可能導致整個平台掛起。目前沒有明確的最佳解決方案。

OpenStax天文學101教科書是什麼？它為何被選中用於這次的教材改造計畫？

Why Are Rivers So Mathematical?

「河流為何如此數學化？」一文探討了河流網絡看似混沌卻又遵循著普世數學定律——哈克定律（Hack's Law，L ~ A^0.6）。這定律指出河流長度與其流域面積的0.6次方成正比，意味著大型流域會比小型流域更為細長。其成因可歸結為水流下坡運輸最優化能源效率的結果，以及河流系統透過侵蝕和沈積不斷自我調整，歷經數千年演化至此種最小能量耗散的穩定配置。近期研究更發現哈克定律也適用於河流三角洲，為地球科學家們帶來了新的謎團。 * 哈克定律 (L ~ A^0.6) 是河流網絡的核心數學關係。 * 能源效率與景觀演化是解釋河流形態的兩大關鍵因素。

文章提到其他運輸網絡（如血管、植物葉脈）也有分形模式，它們是否也遵循哈克定律或類似的最佳比例定律？

文章指出，儘管許多運輸網絡都呈現分支模式，但它們可能遵循不同的最佳比例定律。例如，在三維空間中分支的樹木，其定律會與河流不同。本文特別關注河流是從混沌的地球過程中產生，而非生物演化或都市規劃的結果。

為何哈克定律應用於河流三角洲會令人驚訝？地貌學家可能會如何進一步探索？

令人驚訝之處在於，河流三角洲是分流網絡（沉積物堆積、水分流），與主流入網絡（沉積物運輸、水匯聚）恰好相反。三角洲同時也是平坦且動態的區域，研究難度高。地貌學家目前正思考為何這個數學定律在這種逆向情境中依然適用，這可能揭示了更深層、普遍的有效運輸原則。
